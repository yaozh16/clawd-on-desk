## 七、未来演进与扩展性

### 7.1 当前架构的扩展点

```
┌─────────────────────────────────────────────────────────────┐
```

### 7.3 技术债务

```javascript
// 1. 主进程代码过长（~1200行）
// 建议：拆分为多个模块
// - state-machine.js
// - session-manager.js
// - window-manager.js
// - permission-handler.js

// 2. 缺少类型系统
// 建议：迁移到 TypeScript
// - 更好的 IDE 支持
// - 编译时错误检查
// - 接口定义清晰

// 3. 测试覆盖不足
// 建议：增加集成测试
// - 使用 Spectron 或 Playwright for Electron
// - 覆盖状态机、窗口管理核心逻辑

// 4. 配置分散
// 建议：统一配置管理
// - HTTP 端口
// - 时间常量
// - 状态映射
```

### 7.5 安全考量

```javascript
// 1. 本地 HTTP Server
// 风险：仅监听 127.0.0.1，外部不可访问
// 建议：添加简单的 token 验证

// 2. Hook 脚本权限
// 风险：hook 脚本以用户权限运行
// 建议：文档说明安全边界

// 3. 自动更新
// 风险：GitHub Releases 的 NSIS 安装包未签名
// 建议：获取代码签名证书（Windows SmartScreen）

// 4. 权限审批
// 风险：恶意脚本可能模拟气泡
// 建议：验证请求来源
```
